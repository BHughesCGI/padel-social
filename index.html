Phone access, offline use & event guide

One organiser, one device. Opening the same HTML or link on another phone creates a separate local event. There is no live score sharing. Use text summaries for updates or transfer a JSON backup to move control to another device.

On phones: open an HTTPS link in iPhone Safari or Android Chrome. Keep this tab open during the event. Everything works without a connection after the page has loaded, including fixtures, scoring, the timer and exports. A locked screen is fine: the timer catches up when you return. A timer alert cannot be guaranteed while the phone is locked.

Offline reopening: this single file has no service worker. A hosted link may need a connection after closing, refreshing or browser eviction. Save the HTML on a computer for dependable offline reopening. Local HTML previews in iPhone Files may not run JavaScript; the HTTPS link is the reliable phone option. Home Screen shortcuts alone do not guarantee offline reopening.

Host it yourself: rename a copy of this file to index.html, put it in a folder, then upload that folder using Netlify Drop or your organisation’s static HTTPS hosting. Check the site’s visibility and open the link on a second phone. A free hosting account may be needed to keep and manage a shareable public link. The app itself requires no account or paid service. Hosting does not share tournament data.

Scoring: the configured total is shared between teams: with 16 points, 10–6 and 8–8 are valid. Both partners receive their team’s points. A blank score stays blank until explicitly entered and saved. Rests give no match points.

Mexicano: the first round is random. Later rounds select players fairly, order them by the completed standings, make neighbouring groups of four and pair first + fourth against second + third. Tied ranks allow variety. The same four may meet again because standings drive the groups; new people every round cannot be guaranteed.

Americano: the search prioritises fresh partners, then fewer repeated opponents and groups of four, while balancing appearances and rests. This is a best-effort search, not a promise of a perfect round robin. Player counts, court spaces and event length can make repeats unavoidable. The app reports actual repeats each round.

Fairness: players with fewer appearances play first. Among equally played players, those who rested last round get priority. A long queue can still require consecutive rests. Completed points only affect rankings; scheduled appearances determine rest rotation. Rest counts include generated rounds.

Backups: export JSON after each round. Save it in Files/Downloads. Import validates the file and asks before replacing the current event. Browser storage may be unavailable, cleared or separate between normal, private and Home Screen browsers. Keep one organiser tab open; use the backup when moving devices.

Corrections: History lets you correct a saved score. If later rounds exist, you must confirm discarding them, including any results. The immediately following round is regenerated from the corrected results; further rounds are generated after new results are recorded. Setup is locked once play starts. Add rounds from Current round; finish early only after all scores in the current round are saved.
